# Configuration

Every survey is a directory under `backend/surveys/<survey_id>/`:

| File | Required | Contents |
|---|---|---|
| `survey.yaml` | yes | id, title, description, version, languages, source of the data |
| `questions.yaml` | yes | settings and the question groups |
| `documents.yaml` | no | publication documents (see [Operation](operations.md#build-publication-documents)) |
| `diagram_labels.yaml` | no | labels for placeholders in Mermaid diagrams of publication documents |
| `snapshots/` | written by the suite | previous versions of `questions.yaml` (see [System impact](system-impact.md)) |

The suite finds every directory with a `survey.yaml` (with an `id`) and a
`questions.yaml`. The active survey is chosen in the **Setup** tab, or at start-up
with the environment variable `SURVEY_ID`; without it, the first survey found is
active.

The two example surveys `ai_in_higher_education_de` and `ai_in_higher_education_en`
use every question type, every kind of segmentation and two named scales; they are
generated by `examples/generate.py` and are the best starting point for a new survey.

## `survey.yaml`

```yaml
id: ai_in_higher_education_en
title:
  en: AI in higher education 2026
description:
  en: Survey on the use of AI tools at a university.
version: 1.0
languages: [en]
source:
  type: limesurvey
  survey_id: 863712
```

A title or description may also be a plain string.

## `questions.yaml`

```yaml
settings:
  survey_metadata: {...}
  llm_context: "..."
  scales: {...}
  sample_warnings: {...}
  segmentation: {...}
  report_groups: {...}
question_groups:
  <question_id>: {...}
```

The file is checked whenever it is loaded; errors and warnings are shown in the
**Configuration** tab. Every write by the suite (Config assistant, segmentation editor,
numeric clean-up, structure import) first keeps a snapshot of the previous version.

### `settings.survey_metadata`

| Key | Meaning | Default |
|---|---|---|
| `survey_title` | title per language, `{en: "..."}` | empty |
| `survey_year` | year shown in reports and the dashboard | empty |
| `source_language` | language of the answers and of the configuration: `de` or `en` | `de` |
| `languages` | output languages, e.g. `[en, de, fr, it]` | the source language only |
| `about` | short description for the start page of the dashboard, per language | empty |
| `survey_subtitle`, `survey_period` | subtitle and field period, per language, for the dashboard | empty |
| `summary` | key results for the summary view of the dashboard: a list of `{title, text}`, each per language | empty |
| `contact` | `{name, url}` of the people responsible, on the start page of the dashboard | empty |
| `links` | footer links of the dashboard: `methodology`, `imprint`, `privacy`, `contact`, each a URL or one URL per language; links that are not set are not shown | none |
| `publication_url`, `start_image` | link to the publication and an image for the start page of the dashboard | empty |

### `settings.llm_context`

One or two sentences on the survey (who was asked, about what). They go into every
prompt of the language model and into the translation context.

### Translation settings

| Key | Meaning |
|---|---|
| `settings.glossary` | `{term: {lang: translation}}`, merged over `config/glossary.yaml` |
| `settings.keep_terms` | terms that are never translated (product names, abbreviations) |

### `settings.sample_warnings`

| Key | Meaning | Default |
|---|---|---|
| `minimum_threshold` | groups with fewer respondents are not shown | 5 |
| `warning_threshold` | groups with fewer respondents are marked as small | 10 |

### Question groups

Every question has an id (the key) and these common keys:

| Key | Meaning |
|---|---|
| `handler` | question type, see [Features](features.md#question-types) |
| `columns` | the data columns of the question |
| `label` | short title per language |
| `full_question` | full question text per language (optional) |
| `help` | explanation per language (optional) |
| `summary_schema_override` | sections of the summary of this question (optional) |

Labels and lists are given per language, `{en: "..."}` or `{en: [...]}`. Only the
source language is required; the other output languages are translated (see
[Languages and translations](design/translations.md)).

Keys by question type:

| Type | Keys |
|---|---|
| `single_choice` | `options` (list per language), `ordinal: true` for ordered scales, `scale_order: ascending` or `descending` (direction of the scale), `nps: true` for 0–10, `scale` (name of a named scale instead of options), `sort_order`, `option_colors` |
| `multi_choice` | `options`, `other_column` (column with the texts of an "other" option; listed with the results) |
| `multi_choice_binary` | `item_labels`, `binary_values: {positive: "Yes", negative: "No"}` |
| `matrix_likert` | `row_labels`, `scale` (list per language, or the name of a named scale), `scale_order`, `matrix_segment_chart` |
| `cooperation_matrix` | `row_labels`, `scale` (list or name), ascending from the least to the most important |
| `ranking` | `item_labels` |
| `freetext` | `clustering: {mode, min_cluster_size, max_clusters, max_cluster_pct, hint}`, `item_extraction: {enabled}`, `other_of: <question id>` (this text is the "other, please specify" field of that question) |
| `numeric` | `numeric: {unit, valid_range: {min, max}, bin_count, decimals}` |
| `numeric_matrix` | `item_labels`, `constant_sum`, `unit`, `decimals` |
| `date` | `date: {granularity: day, month or year, dayfirst_slash}` |

`clustering.mode` is `items` (cluster the extracted items, the default when items
exist) or `raw` (cluster whole answers). `hint` is a sentence for the language model
on how the answers should be told apart. `missing_values` (any type) replaces the
list of evasive answers ("don't know", "no answer") that are left out of statistics.

Example (single choice with a named scale, free text with clustering):

```yaml
question_groups:
  satisfaction:
    handler: single_choice
    label: {en: "How satisfied are you with the AI services of your university?"}
    columns: [sat]
    scale: satisfaction
  improve:
    handler: freetext
    label: {en: "What should be improved?"}
    columns: [improve]
    clustering: {min_cluster_size: 3, max_clusters: 8}
```

### Named scales: `settings.scales`

A scale or an order is defined once and referenced by name:

```yaml
settings:
  scales:
    satisfaction:
      context: "satisfaction, from very satisfied to very dissatisfied"
      direction: descending
      points:
        - {label: {en: "Very satisfied"}, polarity: positive}
        - {label: {en: "Rather satisfied"}, polarity: positive}
        - {label: {en: "Rather dissatisfied"}, polarity: negative}
        - {label: {en: "Very dissatisfied"}, polarity: negative}
        - {label: {en: "Don't know"}}
```

| Key | Meaning |
|---|---|
| `context` | what the scale measures; used to translate the short labels |
| `direction` | `descending`: the first point is the highest; `ascending`: the first is the lowest |
| `points` | in their order: `key` (optional, from the label), `label` per language or a text in the source language, `polarity` (`positive`, `neutral`, `negative`; optional) |

Use it with `scale: <name>` in a single-choice, matrix or cooperation-matrix question,
and with `order: <name>` in a segmentation dimension. Embedded lists stay valid. A
point without polarity (such as "don't know") is shown in a neutral colour; answers
that are no point of the scale are left out of the scale metrics.

Code outside the suite that reads `questions.yaml` itself must call
`utils.scales.expand_named_scales(config)` before using the configuration, as the
suite does on load (see [Configuration on load](design/configuration-on-load.md)).

### Segmentation: `settings.segmentation`

```yaml
settings:
  segmentation:
    specific_clusters_min_n: 20
    cross_filters: [[role, site]]
    dimensions:
      - id: role
        label: {en: "Your role at the university"}
        source_question: role
        bucketing: {type: identity}
        enable_specific_clusters: true
      - id: area
        label: {en: "Area"}
        source_question: faculty
        bucketing:
          type: value_mapping
          mapping: {"Computer science": "STEM", "Physics": "STEM", "History": "Humanities"}
          unmapped_strategy: {type: bucket, bucket_label: {en: "Other"}}
      - id: age_group
        label: {en: "Age group"}
        source_question: age
        bucketing:
          type: numeric_buckets
          buckets:
            - {label: {en: "under 25"}, max: 25}
            - {label: {en: "25 to 39"}, min: 25, max: 40}
            - {label: {en: "40 and older"}, min: 40}
      - id: site
        label: {en: "Site"}
        source_column: site
        bucketing: {type: identity}
```

| Key | Meaning |
|---|---|
| `id` | identifier (letters, digits, underscore) |
| `label` | name per language |
| `source_question` or `source_column` | the question (by id) or the data column the groups come from |
| `bucketing.type` | `identity`, `value_mapping` or `numeric_buckets` |
| `bucketing.mapping` | for `value_mapping`: answer → group |
| `bucketing.buckets` | for `numeric_buckets`: half-open intervals `[min, max)`; a missing bound is open |
| `bucketing.unmapped_strategy` | `passthrough` (keep the value), `drop`, or `bucket` with a `bucket_label` |
| `order` | order of the groups: a list of values or the name of a named scale; default: by frequency |
| `value_labels` | `{value: {lang: label}}` for groups without a label from the source question |
| `enable_specific_clusters` | cluster the open answers of every group of this dimension separately |
| `specific_clusters_min_n` | minimum respondents of a group for its own clusters (default 15; also as a setting for all dimensions) |

`cross_filters` lists combinations of dimensions; `settings.segmentation.cross_filter_min_n`
(default 5) is the minimum size of a combination.

### Report groups: `settings.report_groups`

```yaml
settings:
  report_groups:
    people: {order: 1, label: {en: "About you"}, questions: [role, faculty, age]}
```

They order the questions in the Word reports and in the dashboard.

### Analysis settings: `settings.analysis`

| Key | Meaning | Default |
|---|---|---|
| `correlations.alpha` | significance level of the associations | 0.05 |
| `correlations.min_strength` | weakest effect reported | `weak` |
| `correlations.max_per_pair`, `max_per_theme`, `max_cross_theme` | limits of reported associations | 3, 5, 10 |
| `missing_values` | evasive answers left out of statistics (all questions) | a list in German, English, French and Italian |

### Summaries: sections

The summary of a question has three sections by default (description,
interpretation, group differences; numeric questions have their own four). They can be
replaced per question type (`settings.summary_schema_overrides.<type>`) or per question
(`summary_schema_override`), each section with `id`, `label` per language,
`prompt_instruction`, optional `length_hint` (`short`, `medium`, `long`) and
`conditional` (for example `has_segmentation`).

### Other settings

| Key | Meaning |
|---|---|
| `settings.label_replacements` | `{long label: short label}` for charts |
| `settings.matrix_segment_chart` | matrix questions by group in the Word report: `both` (default), `small_multiples`, `mean` or `none`; also per question |

## Limits

- The configuration is checked on load, but not every combination of keys: an
  unknown key is ignored without a warning.
- The source language must be German or English.
- A named scale can be used by single-choice, matrix and cooperation-matrix questions
  and by segmentation dimensions; other types keep their embedded lists.
- When the suite writes the file (Config assistant, segmentation editor, numeric
  clean-up, structure import), comments inside the file are lost; the comment block at
  the top is kept, and the previous version is in `snapshots/`. The YAML editor of the
  **Configuration** tab saves the text as typed, with all comments.
